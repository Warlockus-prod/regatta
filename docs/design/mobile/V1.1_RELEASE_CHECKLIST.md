# v1.1 release - step-by-step checklist (LOCAL build path)

Apple released v1.0 (build 13) - LIVE in the App Store. v1.1 ships:

- **Leaderboard 400 alert** no longer shown to users. `/api/race-result` needs a
  `regatta_sid` cookie the mobile fetch does not send, so it returns 400; the app
  used to surface that as a scary "saved offline" alert. Now a 400 is treated as
  a successful no-op (mobile/app/game/index.tsx).
- **App name unified to "Week to Regatta"** in all 7 App Store locales
  (mobile/asc-metadata/<lang>/name.txt). The iPhone home-screen name is already
  universal via `expo.name` in app.json.

> **Why local, not EAS Cloud?** The Expo account that owns this project is
> unknown / not logged in on this machine, so `eas build` is not an option right
> now. We build the App Store binary locally with Xcode instead. No Expo account
> needed: the Apple Distribution cert + the Xcode-managed App Store profile +
> the ASC API key are all present locally. OTA (EAS Update) is deferred until an
> Expo account is available - see "Deferred: OTA" at the bottom.

Version bookkeeping (`mobile/app.json`, branch `app`):
- `expo.version` **0.14.0** (App Store version string is **1.1**)
- `ios.buildNumber` / `android.versionCode` iterated 14 -> 15 -> 16 -> **17**
  (each native/JS change needs a fresh build number; 17 is the final v1.1 binary)
- `runtimeVersion.policy` = `appVersion` (expo-updates kept but inert - no
  `updates.url`, so it never phones home; safe to leave installed)

**This update grew well beyond the original "leaderboard fix".** The full list
of what ships in v1.1 (build 17) and the web-vs-app parity map live in
`docs/design/mobile/WEB_VS_APP_PARITY.md`. Headline: unified name "Week to
Regatta", new icon, AI assistant ("Ask"), redesigned Rules (RRS/COLREGS +
official sources) and Gallery, glossary category chips, and full es/fr/de/it
for checklist + onboard. Tests: 108/108 green; `tsc --noEmit` clean.

## Step 1 - native project from Expo config (~1 min)

```sh
cd /Users/Andrey/App/all/regatta/mobile
LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 npx expo prebuild --platform ios --clean --no-install
```
Generates `ios/WeektoRegatta.xcodeproj`. `--no-install` skips pods here (next step
runs them with the UTF-8 fix). The `LANG`/`LC_ALL` exports are required - CocoaPods
on Ruby 3.4 throws "Unicode Normalization not appropriate for ASCII-8BIT" without them.

## Step 2 - CocoaPods (~2-4 min)

```sh

LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 pod install
```
Produces `WeektoRegatta.xcworkspace` (use the workspace, never the bare project).

## Step 3 - archive (~10-15 min)

Automatic signing + the ASC API key so xcodebuild can resolve the Xcode-managed
App Store profile headlessly (no interactive Apple login). Do NOT use manual
signing with this profile - it is Xcode-managed and manual+managed is rejected.

```sh
cd /Users/Andrey/App/all/regatta/mobile
CI=1 LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 PATH="/opt/homebrew/bin:/usr/bin:/bin:$PATH" \
xcodebuild \
  -workspace ios/WeektoRegatta.xcworkspace \
  -scheme WeektoRegatta \
  -configuration Release \
  -sdk iphoneos \
  -destination "generic/platform=iOS" \
  -archivePath /tmp/regatta-build/WeektoRegatta.xcarchive \
  CODE_SIGN_STYLE=Automatic \
  DEVELOPMENT_TEAM=547PA2PLLB \
  -allowProvisioningUpdates \
  -authenticationKeyPath "$HOME/.appstoreconnect/private_keys/AuthKey_QBF5228DP3.p8" \
  -authenticationKeyID QBF5228DP3 \
  -authenticationKeyIssuerID c646a296-d7f1-418a-ac78-4ede7aacd995 \
  archive
```
Success marker: `** ARCHIVE SUCCEEDED **` and `WeektoRegatta.xcarchive` on disk.

## Step 4 - export + upload to App Store Connect (~3-5 min)

`ExportOptions.plist` (method app-store-connect, automatic signing,
manageAppVersionAndBuildNumber=false so build 14 is preserved):

```sh
cd /Users/Andrey/App/all/regatta/mobile
xcodebuild -exportArchive \
  -archivePath /tmp/regatta-build/WeektoRegatta.xcarchive \
  -exportOptionsPlist /tmp/regatta-build/ExportOptions.plist \
  -exportPath /tmp/regatta-build/export \
  -authenticationKeyPath "$HOME/.appstoreconnect/private_keys/AuthKey_QBF5228DP3.p8" \
  -authenticationKeyID QBF5228DP3 \
  -authenticationKeyIssuerID c646a296-d7f1-418a-ac78-4ede7aacd995 \
  -allowProvisioningUpdates
```
This produces `export/WeektoRegatta.ipa`. Then upload + validate:

```sh
xcrun altool --validate-app  -f /tmp/regatta-build/export/WeektoRegatta.ipa -t ios \
  --apiKey QBF5228DP3 --apiIssuer c646a296-d7f1-418a-ac78-4ede7aacd995
xcrun altool --upload-app    -f /tmp/regatta-build/export/WeektoRegatta.ipa -t ios \
  --apiKey QBF5228DP3 --apiIssuer c646a296-d7f1-418a-ac78-4ede7aacd995
```
(`altool` reads the .p8 from `~/.appstoreconnect/private_keys/`.) After upload,
the build shows in ASC under TestFlight in ~5-15 min once Apple finishes
processing.

## Deferred: OTA (EAS Update)

Once an Expo account is available and logged in (`npx eas-cli login`):
`eas update:configure` adds `updates.url` + `extra.eas.projectId`; flip
`runtimeVersion.policy` to `fingerprint`; rebuild once so the binary embeds the
update URL. After that, JS-only fixes ship in ~30 s via
`eas update --channel production` with no Apple review. Native changes still need
a full build + submit.

## Rollback

- Bad binary cannot be rolled back through Apple - remediation is to ship v1.2
  quickly (or, once OTA is live, push a JS revert).
